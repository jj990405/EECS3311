# 기능 시연 영상 촬영 가이드

작성 기준: 2026-11-13, Stage 2 PDF 4쪽. 아직 녹화·업로드된 영상이나 실제 타임스탬프가 아니다. 아래 시간은 촬영 분량을 잡기 위한 권장 배분이다.

## 과제에서 요구하는 것과 권장하는 것

| 항목 | 과제의 명시 요구 | 이번 프로젝트 권장안 |
| --- | --- | --- |
| 영상 개수 | 고정 개수 없음. 기능별 또는 합본 가능 | GUI 1개 + CLI 1개. 길어지면 공부 기능을 별도 영상으로 분리 |
| 영상 길이 | 고정 분/최대 길이 명시 없음 | 총 약 20–25분 목표. AI 대기·입력량에 따라 늘려도 기능을 누락하지 말 것 |
| 화면 | 실제 실행 앱의 입력·동작·결과. 전체적으로 GUI와 CLI 둘 다 | GUI는 EXE 실행부터, CLI는 별도 EXE 실행부터 |
| 설명 | 기능 ID/이름, 필요한 입력, 결과, AI가 관여하는 지점, 적절한 대안/오류 | 각 장면 시작에 `F02 — Syllabus extraction` 같은 제목 + 1–2문장 설명 |
| 나레이션/언어 | 음성 여부·언어·얼굴 카메라 형식은 별도 지정 없음. 설명 자체는 필요 | 영어 짧은 나레이션 권장. 음성이 없으면 읽을 수 있는 영어 자막으로 설명. 얼굴 촬영은 필요 요건에 없음 |
| 제출 | 기능별 링크+직접 타임스탬프를 보고서에. 교수/TA가 접근 요청 없이 볼 수 있어야 함 | 비공개 접근 제한 대신 접근 가능한 링크. 업로드 후 로그아웃/시크릿에서 재생 확인 |

**슬라이드나 스크린샷만으로 대체하면 안 된다.** 입력한 다음 결과가 실제로 생기는 것을 녹화한다. 컷 편집/AI 대기 구간 생략은 표시하고, 기다리는 화면을 저장된 결과로 바꿔 실제 실행인 척하지 않는다.

## 촬영 준비

1. `Project/Study Agent.exe`를 더블클릭한다. `.exe`와 `app/`, `runtime/`를 함께 둔다. PowerShell은 GUI 실행에 필요 없다. `Study Agent CLI.exe`는 콘솔 프로그램이라 텍스트 창이 정상이다.
2. 개인 데이터 대신 별도 데모 실행 폴더를 사용한다. 앱을 닫고 EXE 2개와 `app/`, `runtime/`, `.env.example`을 복사한다. 실제 `.env`는 로컬에서만 설정하고 화면에 열지 않는다. 데모는 원본 `data/`를 덮어쓰지 않는다.
3. 한 학기(예: Fall 2026), 서로 다른 난이도의 두 과목(EECS3311 HIGH, EECS2021 LOW), 실제 강의계획서, 짧은 공부 자료, 과제 안내를 준비한다. 날짜가 지난 경우 이번 주/다음 주의 수동 일정도 만들어 우선순위와 알림을 보여준다. 실제 syllabus의 날짜를 바꾸어 설명하지 않는다.
4. 분류 실수 예시용 강의 파일 하나를 Assignment Specifications로 넣어 N01에서 고친다. 중복 업로드 예시와 날짜 미정 평가 하나를 준비한다. 실제 데이터/테스트용 자료를 명확히 구분한다.
5. 글자가 읽히도록 창을 최대화하고 해상도/녹화 결과를 확인한다. 알림 팝업·메일·다른 앱은 닫는다. 키 입력창, `.env`, API 관리 페이지, 비밀키는 촬영하지 않는다.
6. 10초 테스트 녹화 후 글자·마이크·앱 소리가 들리는지 재생한다. 녹화 도구는 OBS의 공식 [Quick Start](https://obsproject.com/kb/quick-start-guide)를 따라 화면/오디오 소스를 설정하거나, [Clipchamp 화면 녹화](https://support.microsoft.com/en-us/clipchamp/how-to-make-a-screen-recording)를 사용한다.

저작권/개인정보 없는 짧은 재현용 자료는 [sample-materials](sample-materials/)에 준비했다. `demo-syllabus.txt`, `week3-lecture.txt`, `design-review-specification.txt`이며 전부 합성 예제라고 표시되어 있다. 실제 EECS3311 강의계획서 PDF와 혼동하지 않는다. PDF 미리보기 장면에는 본인이 가진 PDF를 사용한다.

타이머 자연 만료/알람은 실제 15분을 기다리는 별도 촬영을 해 A07 뒤에 짧게 붙이는 것이 가장 명확하다. 기다린 구간은 “15 minutes later”로 표시해 줄여도 된다. 개발용 1초 테스트를 실제 15분 실행인 척 보여주지 않는다. 앱이 닫힌 상태에서도 알람이 울린다고 설명하지 않는다.

현재 AI 메뉴에는 단일 syllabus/week 제안과 일괄 분석이 함께 있다. A04 뒤에 Suggest lecture week에서 자료의 week 번호를 승인해 F01의 주차 매칭도 꼭 보여준다. 날짜가 학기 밖인 입력 하나는 오류를 보여주고 올바른 날짜로 수정한다. 기존 일정을 잘못 중복 생성하지 않는다.

## 영상 B — CLI, 약 6–9분

`Study Agent CLI.exe`를 더블클릭하면 프롬프트가 뜬다. 이 콘솔 창은 CLI의 정상 실행 화면이다. 터미널 명령으로 실행할 경우 JAR은 `java -jar codex/build/target/study-agent.jar --cli`, EXE는 `"Study Agent CLI.exe"`다. EXE에 사용자 인자 `--data`를 전달하면 jpackage 기본 인자가 대체되므로 `--cli --data <별도경로>`처럼 **--cli도 같이** 전달한다.

선택 번호는 매번 화면 목록에 맞춘다. 이전 녹화의 숫자를 맹목적으로 복사하지 않는다.

| 장면 | 실제 명령 / 입력 순서 | 화면에서 확인할 것 |
| --- | --- | --- |
| B01 F01/N04 | `help` → `setup`; 학기/과목 안내를 따라 입력; 날짜 `20260901`, `20261231`; 난이도 숫자 선택 → `material add` → `tree` | 안내형 입력, RGB 코드 불필요, 생성된 트리/파일 |
| B02 F02/F01 | `ai syllabus` → 자료 선택 → `proposals` → `approve` 하나, `reject` 하나. `ai week` → 강의 자료 → 승인 | AI 후보가 승인 전 저장 안 됨, 주차 변경 |
| B03 F03/F04/F09/F07 | `deadline add` → `timeline` all/week/month + 검색/과목 → `calendar` 월 → `complete`/`progress` → `deadline notify`/`reminders`/`notifications` | 실제 일정/필터/진행률, notification 설정. 날짜 한 번 잘못 입력 후 교정 |
| B04 F06/F11/F12 | `ai references` → 일정 → `ask` → 실제 자료 질문 → `summary create`/`summary list` | 업로드 파일 추천, 페이지 출처, 생성/저장 요약 |
| B05 F13/F14 | `quiz create` → 범위/개수/난이도 → `quiz take` → 답 → `essay create`/`essay take` → `proposals`/`approve` → `essay list` → `self assess`/`weak topics`/`weak advice` | 점수와 피드백, 승인 후 essay 저장, 약점 |
| B06 F05/F08/F10/F15 | `study week` → `ai schedule` → before/after → `approve` → `weekly brief` → `history` → `history delete` | GUI에서 저장된 공부시간을 같은 데모 데이터의 CLI에서 읽기; 일정 변경/brief/history. CLI에는 실행 타이머가 없고 기록 조회만 있음 |

GUI와 CLI가 동일한 데모 폴더의 `data/`를 쓰게 하면 저장 공유도 쉽게 보여준다. 동시에 실행해서 쓰기 충돌을 유발하지 말고 GUI를 닫은 뒤 CLI를 실행한다.
