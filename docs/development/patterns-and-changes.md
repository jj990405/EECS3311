# Patterns and Stage 1 changes

Verified from the implementation on 14 November 2026. There are **six distinct GoF patterns**, without counting Simple Factory or repeated Strategy uses as extra distinct patterns. Source folder: `src/main/java/eecs3311/studyagent/`.

| Pattern | Participants / actual methods | Design problem and why this is a real use | Stage 1 alignment |
| --- | --- | --- | --- |
| Facade | `AgentController`; clients `MainWindow`, `CommandLineInterface`; e.g. `uploadMaterial`, `answerQuestion`, `planScheduleChange`, `approveProposal` | Both interfaces need consistent storage, validation, retrieval and AI orchestration. They call a common application boundary rather than reimplementing each workflow. | Role retained; some planned tool services consolidated into direct controller/helper calls. |
| Composite | Component `WorkspaceNode.label/children`; composite `WorkspaceBranch`; leaf `WorkspaceLeaf`; builder `WorkspaceTree.build` | Semesters, courses and category branches contain children; files have an empty child list. GUI and CLI recursively traverse the same interface. | Role retained as a view projection. `WorkspaceBranch.Kind` replaces separate persisted entity-composite classes. |
| Adapter | Target `LlmClient.complete`; adapter `HttpLlmClient.complete`; adaptee boundary HTTPS chat-completions protocol | The adapter translates application prompts to authenticated JSON HTTP and extracts response content. Task services depend on the small target interface; tests can substitute it. | Configurable protocol adapter replaces the planned vendor-specific `DeepSeekClient`. No claim that a separate SDK adapter class exists. |
| Observer | Subject `DataStore.addChangeListener/changed`; callback contract `Runnable`; `MainWindow` registers via `AgentController.addChangeListener` | Store mutations notify GUI callbacks, which dispatch refresh on the Swing EDT. The store does not need to know concrete GUI widgets. | Participants changed. Timer is polled with Swing Timer; do not claim `StudyTimer` implements a custom Subject or `TimerPanel` implements Observer. No listener detach method currently. |
| Command | `AgentCommand.execute`; add/edit/delete/week command records; invoker `CommandInvoker.propose/approve/reject/replace`; receiver `DataStore` | AI suggestions must not mutate the schedule before review. Commands encapsulate the delayed receiver operation; approval executes it, rejection removes it. Essay-grade updates use an `AgentCommand` lambda. | Role retained. `EditDeadlineCommand` replaces planned name `UpdateDeadlineCommand`; grade command uses lambda instead of named `UpdateGradeCommand`. Pending queue is transient. |
| Strategy | `PriorityStrategy.order` + `PriorityRecommender`; `ExplanationStrategy.instruction/forDifficulty` returns low/medium/high lambdas | Ordering policy is separate from filtering; course difficulty selects a different explanation policy without rewriting the Q&A pipeline. | Priority/explanation policies retained. One priority implementation exists. No `GradingStrategy` family: MCQ grading is deterministic in `StudyArtifacts`, essay grading is an AI workflow. |
| Simple Factory (additional, not counted among the six) | `DocumentReaderFactory.getReader` → `PdfReader/PptxReader/DocxReader/TxtReader` implementing `DocumentReader` | Selects the correct extraction implementation from the file extension and centralizes construction. | Matches the course's general Factory description. This is not a GoF Factory Method inheritance hierarchy or Abstract Factory. |

The rendered [class/architecture sheets](../design/implemented/architecture/README.md) give roles and method-level evidence. The [behavior sheets](../design/implemented/behavior/README.md) show when those collaborators run.

## Complete-source preparation follow-up - 14 November 2026

After further owner screenshots, source preparation now runs after upload rather than waiting for individual study commands. `StudySources` reads every page, invokes the existing `LlmClient` Adapter's optional image operation for sparse/image-heavy PDF pages and embedded PPTX pictures, and persists complete text plus a `SourceIndex` inverted index. Quiz scopes consume the whole prepared source, batching long scopes instead of sharing a fixed front-prefix budget across files. Existing uploads can be indexed through the AI menu or CLI `material index`. No new design-pattern category is claimed.

F11 course chat now defaults to all course materials with an explicit selected-file option. Assessment queries include syllabus/saved scope, and only previous same-course student questions enter memory context; old AI answers/citations are not reintroduced as evidence. Invalid citations cause regeneration with an exact allowed-physical-page list. `ReadableText` renders Markdown emphasis/headings safely. F13's week scope offers file selection when assignments are missing, without inventing a lecture week. The owner explicitly approved full text/image transmission to the configured OpenAI API. Actual full-source preparation, cache reuse, DBC/Architecture/all-lecture quizzes and both reported assessment questions then passed the bounded checks in verification.md. Image reading is model-assisted and can misread diagrams; it is not guaranteed lossless transcription.
