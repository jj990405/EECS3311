# Patterns and Stage 1 changes

Verified from the implementation on 14 November 2026. There are **six distinct GoF patterns**, without counting Simple Factory or repeated Strategy uses as extra distinct patterns. Source folder: `src/main/java/eecs3311/studyagent/`.

| Pattern | Participants / actual methods | Design problem and why this is a real use | Stage 1 alignment |
| --- | --- | --- | --- |
| Facade | `AgentController`; clients `MainWindow`, `CommandLineInterface`; e.g. `uploadMaterial`, `answerQuestion`, `planScheduleChange`, `approveProposal` | Both interfaces need consistent storage, validation, retrieval and AI orchestration. They call a common application boundary rather than reimplementing each workflow. | Role retained; some planned tool services consolidated into direct controller/helper calls. |
| Composite | Component `WorkspaceNode.label/children`; composite `WorkspaceBranch`; leaf `WorkspaceLeaf`; builder `WorkspaceTree.build` | Semesters, courses and category branches contain children; files have an empty child list. GUI and CLI recursively traverse the same interface. | Role retained as a view projection. `WorkspaceBranch.Kind` replaces separate persisted entity-composite classes. |
| Adapter | Target `LlmClient.complete`; adapter `HttpLlmClient.complete`; adaptee boundary HTTPS chat-completions protocol | The adapter translates application prompts to authenticated JSON HTTP and extracts response content. Task services depend on the small target interface; tests can substitute it. | Configurable protocol adapter replaces the planned vendor-specific `DeepSeekClient`. No claim that a separate SDK adapter class exists. |
| Observer | Subject `DataStore.addChangeListener/changed`; callback contract `Runnable`; `MainWindow` registers via `AgentController.addChangeListener` | Store mutations notify GUI callbacks, which dispatch refresh on the Swing EDT. The store does not need to know concrete GUI widgets. | Participants changed. Timer is polled with Swing Timer; do not claim `StudyTimer` implements a custom Subject or `TimerPanel` implements Observer. No listener detach method currently. |
| Command | `AgentCommand.execute`; add/edit/delete/week command records; invoker `CommandInvoker.propose/approve/reject/replace`; receiver `DataStore` | AI suggestions must not mutate the schedule before review. Commands encapsulate the delayed receiver operation; approval executes it, rejection removes it. Essay-grade updates use an `AgentCommand` lambda. | Role retained. `EditDeadlineCommand` replaces planned name `UpdateDeadlineCommand`; grade command uses lambda instead of named `UpdateGradeCommand`. Pending queue is transient. |
| Strategy | `PriorityStrategy.order` + `PriorityRecommender`; `ExplanationStrategy.instruction/forDifficulty` returns low/medium/high lambdas | Ordering policy is separate from filtering; course difficulty selects a different explanation policy without rewriting the Q&A pipeline. | Priority/explanation policies retained. One priority implementation exists. No `GradingStrategy` family: MCQ grading is deterministic in `StudyArtifacts`, essay grading is an AI workflow. |
| Simple Factory (additional, not counted among the six) | `DocumentReaderFactory.getReader` → `PdfReader/PptxReader/DocxReader/TxtReader` implementing `DocumentReader` | Selects the correct extraction implementation from the file extension and centralizes construction. | Matches the course's general Factory description. This is not a GoF Factory Method inheritance hierarchy or Abstract Factory. |

The rendered [class/architecture sheets](../design/implemented/architecture/README.md) give roles and method-level evidence. The [behavior sheets](../design/implemented/behavior/README.md) show when those collaborators run.

## Consolidated change record

| Original → implemented | Reason | Impact / affected requirements and architecture |
| --- | --- | --- |
| `LLMClient`/`DeepSeekClient` → `LlmClient`/configurable `HttpLlmClient` | Owner chose OpenAI; preserve provider boundary | AI workflows remain behind Adapter. Model/endpoint configured locally; all AI feature sequences updated. |
| `ToolManager`, `Tool`, `ToolResult` registry → explicit Java helper calls from facade/planner | Current finite workflows do not need a generic dynamic registry | Retrieval, validation and planning still execute Java work around the LLM. No dynamic tool-discovery subsystem is claimed. Affects F02/F06/F08/F11/F14. |
| `Planner` → `SchedulePlanner` | Separate schedule interpretation from controller and persistence | F08 supports add/edit/delete/clarification, review and one action per request. |
| `MemoryManager`/`InteractionRecord` → `InteractionHistory.Entry` + `StudyArtifacts` | Separate conversation context from generated items/results | F11/F15 retain recent memory and persistent records; F12–F14 use artifact persistence. |
| Named `FileNameValidator` tool → local checks in `ReferenceSelector`, Q&A and advice boundaries | Validate the model output against the exact candidate set supplied | F06/F11/F14 reject/ignore unknown source identifiers; no independent factual-proof checker. |
| Timer Subject/Observer → store callbacks + Swing timer polling | Keep countdown rendering on EDT and store mutation notifications shared across screens | F05 remains countdown/pause/resume/alarm/records; Observer's subject changed to `DataStore`. |
| Named grading strategies → local MCQ grading + AI essay draft and approved score | Separate exact answer comparison from reviewed model judgment | F13 functionality remains, but grading Strategy claim removed. Explanation/priority retain Strategy. |
| GUI automatic AI after upload → explicit AI buttons after deterministic batch upload | Owner requested upload everything first and control API use | F01 week assignment and F02 extraction still available; N01 classification and N03 bulk analysis are reviewed steps. CLI lecture upload retains its automatic week proposal and asks for approval. |
| Nonselected calendar weeks show dots → all weeks show course/title labels + course filter + day editor | Make deadlines usable without selecting every week | F03 keeps month navigation and adds empty-day create/edit. Affected `CalendarPanel/MainWindow`, SD03. |
| Paragraph summary popups → saved study guide tab with headings/bullets/bold and source button | Owner needs usable study material beside original PDF | F12 retained; `StudyNotesPanel`, SD09b; generated facts require review. |
| Wide quiz option popups → `QuizDialog` hosting `QuizSessionPanel` with question navigation, wrapping choices, progress and review | Long choices previously exceeded screen width | F13 retained with file/week/all scope, count, difficulty and type; MCQ and essay stored separately. |
| Raw RGB/date input → swatches/automatic color and typed compact date/calendar picker | Remove unnecessary setup knowledge and strict punctuation | N04 extends F01/F03. Color identifies course in tree/calendar; timeline uses a thin muted marker with no red/green or course-tinted background. |
| Fixed viewer → optional split workspace with closable PDF/calendar/notes tabs | Owner requested source alongside main work and full width after closing tabs | N02, `MainWindow/PdfPreviewPanel`; originals stay unchanged. |
| Individual extraction only → explicit bulk review/Add all/TBD decisions and daily unknown-date reminder | Reduce repetitive approval while keeping date uncertainty visible | N03 extends F02/F07; duplicate prevention and date validation still run. |
| Short-prefix classification → multi-position sampling and full-document review when uncertain | Owner found mixed bulk uploads inaccurate and authorized fuller API reading | N01; shared `DocumentClassification`, pre-upload `UploadReviewDialog`, strict complete-response validation; no sorting applies before review. |
| No reset/classification flow → reviewed category moves and confirmed local reset | Recover from wrong folders and restart a workspace | N01/N05 additions; stored copies move, original external files and `.env` stay. |

These are declared implementation differences, not a claim of literal class-for-class identity with Stage 1. All original feature IDs are accounted for in the feature matrix.
